# Haskell Rogue-like

## Авторы
Окунев Данила, Лавицкая Александра

## Описание
Консольная rogue-like игра, написанная на Haskell. Включает генерацию уровней, пошаговую боевую систему, инвентарь, экипировку и простое поведение врагов.

## Запуск

```bash
cabal build
cabal exec haskell-rogue-like
````

## Структура проекта

- app/Main.hs - UI, ввод, игровой цикл
- src/Game/Types.hs - основные типы данных
- src/Game/Logic.hs - игровая логика (бой, инвентарь, поведение врагов)
- src/Game/Generation.hs - генерация уровней и предметов
- src/Game/Config.hs - константы (размеры и т.д.)
- test/Spec.hs - тесты

## Производительность

Игра работает в пошаговом режиме (turn-based), поэтому производительность определяется стоимостью одного хода.

### Сложность основных операций

#### 1. Движение игрока

```
tryMovePlayer
```

* Простые проверки: `O(1)`

* Доступ к карте: `O(W)`
(W - ширина карты)

* Проверка врагов: `O(log N)`
(N - количество врагов)

**Итого:** `O(max(W, log N))`

#### 2. Атака

```
playerAttackEnemy
```

* Поиск врага: `O(log N)`
* Обновление Map: `O(log N)`

**Итого:** `O(log N)`

#### 3. Ход врагов

```
enemyTurn
```

* Перебор всех врагов: `O(N)`
* Для каждого врага:

  * Поиск в Map: `O(log N)`
  * Проверка соседних клеток и доступ к карте: `O(W)`
  * Движение: `O(log N)`

**Итого:** `O(N (log N + W))`

Для небольших карт с фиксированной шириной `W` можно считать `O(N log N)`.

#### 4. Генерация уровня

```
tryBuildFloor
```

Состоит из:

* генерации карты: `O(W × H)`
* BFS (связность): `O(W × H)`
* размещения объектов: `O(N log N)`

**Итого:** `O(W × H + N log N)`

#### 5. Инвентарь

```
useOrEquip
dropInvSlot
```

Список (`[Item]`) - доступ по индексу: `O(N)`

**Итого:** `O(N)`

---

### Используемые структуры данных

| Структура         | Назначение     | Причина выбора                |
| ----------------- | -------------- | ----------------------------- |
| `Map`             | враги, сундуки | быстрый поиск `O(log N)`      |
| `List`            | инвентарь      | простота, малый размер        |
| `Grid ([[Tile]])` | карта          | быстрый доступ по координатам |

---

### Узкие места и потенциальные оптимизации

В текущей реализации карта представлена как список списков (`g !! y !! x`), что в худшем случае даёт сложность `O(W + H)` при доступе к конкретной клетке. Линейный доступ к инвентарю через `takeNth` имеет сложность `O(N)`, что допустимо из-за малого размера инвентаря. BFS для проверки связности пола при генерации уровня выполняется несколько раз и имеет сложность `O(W × H)`.

Для оптимизации можно рассмотреть замену структуры `Grid` на `Array` или `Vector`, что позволит получать доступ к клеткам за `O(1)`. Также возможно кэшировать результаты компонентов связности пола, чтобы не пересчитывать их при каждой проверке.

---

### Итог

Производительность текущей реализации достаточна для консольной игры. Основные операции с врагами и предметами укладываются в сложность `O(log N)` или `O(N log N)`, где `N` - количество врагов. Основная нагрузка приходится на генерацию уровня, которая включает построение карты, проверку связности и размещение объектов; эта операция выполняется редко, при переходе на новый этаж, поэтому на общую производительность игры сильно не влияет.

* поведение врагов

Все тесты можно запустить через
```
 cabal test
```
