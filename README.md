# Haskell Rogue-like

## Авторы
Окунев Данила, Лавицкая Александра

## Описание
Консольная rogue-like игра, написанная на Haskell. Реализованы генерация уровней, сражение с врагами, управление инвентарём и экипировкой, а также простое поведение противников.

## Запуск

```bash
cabal build
cabal exec haskell-rogue-like
````

## Структура проекта

- app/Main.hs - UI, ввод, игровой цикл
- src/Game/Types.hs - основные типы данных
- src/Game/Logic.hs - игровая логика (бой, инвентарь, поведение врагов)
- src/Game/Generation.hs - генерация уровней и предметов
- src/Game/Config.hs - константы (размеры, баланс, тексты и т.д.)
- test/Spec.hs - тесты

## Производительность

Игра работает в пошаговом режиме, поэтому производительность оценивается через стоимость одного хода.

### Движение игрока

Когда игрок пытается сделать шаг, игра сначала проверяет, жив ли персонаж - это `O(1)`. Затем происходит обращение к карте, чтобы узнать, что находится в целевой клетке. Карта реализована как список списков (`[[Tile]]`), поэтому доступ к клетке через `(g !! y) !! x` требует сначала пройти `y` строк (высота карты), а затем `x` элементов внутри строки (ширина карты). В худшем случае это даёт сложность `O(H + W)`, где `H` и `W` - размеры карты. После этого игра проверяет, есть ли в этой клетке враг, используя `Map`, где поиск выполняется за `O(log N)`, где `N` - количество врагов. Таким образом, общая сложность движения игрока составляет `O(H + W + log N)`.

### Атака

Когда игрок атакует врага, игра ищет его в `Map` (`O(log N)`), затем обновляет его здоровье или удаляет, если враг мёртв (тоже `O(log N)`). Поэтому атака - одна из самых быстрых операций, её сложность определяется только количеством врагов: `O(log N)`.

### Ход врагов

Это самая затратная операция в игровом цикле. Сначала все враги сортируются по координатам, что требует `O(N log N)` времени, где `N` - количество врагов. Затем игра проходит по каждому врагу. Для каждого из них нужно проверить, может ли враг ударить игрока (проверка четырёх соседних клеток), или выбрать клетку для шага. Каждая проверка соседней клетки требует обращения к карте, что даёт вклад `O(H + W)`. В результате ход всех врагов занимает `O(N log N + N * (H + W + log N))`, что упрощается до `O(N * (H + W) + N log N)`. На практике это не критично, так как врагов на уровне не более 11, а карта имеет фиксированные размеры.

### Генерация уровня

Эта операция выполняется только при переходе на новый этаж. Сначала строится карта с озёрами и руинами, что требует обхода всех клеток - `O(H * W)`. Затем с помощью поиска в ширину проверяется связность пола - это тоже требует обхода всех клеток, `O(H * W)`. После этого на карте случайным образом размещаются враги и сундуки, что даёт вклад `O(N log N)`. В итоге генерация уровня занимает `O(H * W + N log N)`. Поскольку эта операция происходит редко, она не влияет на плавность игры.

### Инвентарь

Доступ к предметам в инвентаре осуществляется по индексу в списке через функцию `takeNth`, которая в худшем случае проходит до указанного индекса, поэтому требует времени `O(M)`, где `M` - размер инвентаря. На практике инвентарь редко превышает 20-30 предметов, поэтому линейный поиск остаётся приемлемым.

## Тестирование

Проект покрыт unit-тестами, которые проверяют генерацию уровней, баланс характеристик, боевую систему, работу инвентаря и предметов, движение игрока, поведение врагов, а также граничные случаи.

Все тесты можно запустить через
```
 cabal test
```

## Качество кода

Код опирается на чистые функции, минимизирует использование IO, разделяет логику и интерфейс, применяет стандартные комбинаторы вместо явного паттерн-матчинга, соблюдает рекомендации HLint и придерживается консистентного форматирования.
